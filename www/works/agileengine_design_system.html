MY APPROACH

three decisions that made the program self-sustaining

1. Foundation, not bespoke Picked MUI + Material Design as the base — engineers ship faster and the system survives team transitions. No vanity in-house framework to maintain.
2. Stakeholders own identity Department logos came out of cross-functional workshops — owners generated, voted, and cared about the result. Designers polished, didn't dictate.
3. Delegated facilitation Once the workshop format was proven, I handed it off. The system kept producing aligned identities without me in the room — the only way to scale.

FOUNDATIONS

colour system, contrast tokens, and visual hierarchy

Accessibility Every colour token is paired with a WCAG 2.1-validated contrast ratio. Hover, focus, selected and disabled states are baked into the tokens — not patched at the page level.
Visual hierarchy Main / Secondary / Tertiary / Action roles applied consistently across all components, so engineers can compose new screens without re-deciding semantics.

TYPOGRAPHY

a deliberate type scale, accessible across every product

H1 — H8 scale Eight tested heading sizes, with weights and letter-spacing defined per role. The scale survives marketing pages, product UI, and dashboards equally well.

COMPONENTS

buttons, inputs, checkboxes, radio, sliders, alerts and date pickers

States, not screens Each component ships every state — enabled, hovered, focus-visible, disabled, error — as a Figma variant. Engineers consume the same matrix in code via MUI props.
Responsive grid A single 12-column grid scales from Extra Small 444 px → Tablet 900 px → Desktop 1200 px, with consistent gutters and breakpoints.

ALERTS & PICKERS

feedback patterns and calendrical UI built from the same tokens

Alert system Five severity levels × three styles × dismissable / actionable — all derived from the colour and shape tokens, so visual consistency is automatic.
Date pickers Single-date and range pickers, plus combined date-and-time, ship as ready Figma components and match MUI props one-to-one.

MULTI-BRAND

one foundation, many sub-brands

Sub-brand: Rocky The Rocky logotype, mark variants, and reverse-on-dark applications were folded into the same system — so the engineering studio and its sub-services share infrastructure but keep distinct identities.
Department identities Each department got its own logotype, voice, and asset set — generated in stakeholder workshops, polished by designers, and folded into the same library. One source of truth, many faces.

OUTCOMES

a system that keeps producing — without me in the room

Powers multiple internal products Engineers consume MUI components and Figma variants from one matrix — no forks, no drift across product lines.
Company-wide brand assets Department logos, email signatures, letterheads, and document templates all draw from the same library. One source of truth, every team aligned.
